## 1. 数值标记约定

| 标记 | 含义 |
|---|---|
| `[待定]` | 数值未定，等数值表补齐后回填。逻辑结构已定，不阻塞开发。 |
| `[待定:口径]` | 数值未定，但已说明该数的量纲/取值范围/影响面，例如 `[待定:正整数, 单位=格]` |
| `[假设-N]` | 策划自行拍板的规则，索引见 [10-待确认项与假设](10-待确认项与假设.md)。**改它会连带改别处，改动前先看假设条目。** |
| `[冲突]` | 现有资料（gameset.md / food.xlsx / buff.xlsx）之间不一致，必须在 [10](10-待确认项与假设.md) 里裁决 |

公式书写规范：
- 变量用下划线式英文缩写并当场定义，如 `客流_基础`。
- 概率一律写成百分比数值，如 `12%`，配置表里存 `0.12`。
- 时间在备货/备餐阶段用**分钟**，在出摊阶段用**游戏刻（tick）**，两者不混用。
- 取整规则：金钱向下取整到 1 元；层数、份数向下取整；概率不取整。
- 除法一律注明"向上取整/向下取整/四舍五入"，不写"约等于"。

## 2. 时间单位

| 单位 | 定义 | 换算 |
|---|---|---|
| 轮（Run） | 一次完整游戏进程，7 天 | 7 回合 |
| 回合 / 日（Day） | 一个营业日 | 备货 + 备餐 + 出摊 |
| 游戏刻（tick） | 出摊阶段模拟的最小时间步 | 200 tick = 1 实时秒；出摊共 60 实时秒 = 12000 tick |
| 分钟（min） | 备货/备餐阶段的行动时间货币 | 每阶段共 360 min（8:00-14:00 / 14:00-20:00） |
| 游戏秒 | 出摊阶段对外显示的"店内时间" | 1 tick = `[待定: 建议 1.2]` 游戏秒 |

- 出摊的 4 小时营业时间（20:00-24:00）压缩进 12000 tick。取 1 tick = 1.2 游戏秒时，`出餐时间 = 50 tick` 正好等于店内 1 分钟，与 `food.xlsx` 的取值最贴合 —— 见 [假设-2]。
- **渲染帧与 tick 解耦**：渲染按显示器刷新率插值，逻辑只认 tick。策划改数值不涉及帧率。

## 3. 核心名词

### 3.1 阶段与行动

| 词 | 英文/ID | 说明 |
|---|---|---|
| 备货 | `STOCK` | 8:00-14:00，采购食材原料，主货币是**分钟**和**钱** |
| 备餐 | `PREP` | 14:00-20:00，定菜单、定价、预加工，主货币是**分钟**、**台面格**、**钱** |
| 出摊 | `SELL` | 20:00-24:00，实时 60 秒，主货币是**游戏刻** |
| 结算 | `SETTLE` | 出摊结束后的评分、加成三选一 |
| 局外 | `META` | 一轮 7 天结束后的技能/解锁界面 |

### 3.2 餐品与属性

| 词 | ID | 说明 |
|---|---|---|
| 餐品 | `Food` | 可上架售卖的单个 SKU，如「酸辣粉」 |
| 属性（Tag） | `Tag` | 餐品的固有分类，一个餐品最多 3 个。当前共 **12 种**：**速食、主食、魔鬼辣、炸货、现做食品、现做饮品、饮品、凉菜、烤物、汤羹、甜点、卤味** |
| 词条（Trait） | `Trait` | 绑定某个属性的全局加成条目，如「速度为王」绑定速食。全表 **12 条**，每个属性一条。见 §3.3 |
| 特性（Perk） | `Perk` | 餐品自带的被动效果，主要作用是**产出词条层数**，如方便面「每售出 8 份，所属已激活词条层数 +1」 |
| 上架 | `OnMenu` | 把餐品放进今日菜单。只有上架的餐品才能被顾客点、才能参与词条门槛计数 |
| 上架款数 | `MenuCount(tag)` | 今日菜单中拥有该属性的餐品数量。词条激活的唯一判定依据 |

### 3.3 词条系统（本作的核心增益循环）

| 词 | 说明 |
|---|---|
| 激活门槛 | 某属性**上架款数 ≥ N** 时该属性对应词条激活。N 因词条而异（3~6 款），见 `配表/Trait` 的「激活上架款数」 |
| 层数 X | 词条强度的唯一变量，**永久累积、不设上限**。跨日、跨轮都保留，只增不减 |
| 阶梯档位 | 词条效果**按 X 落在哪个区间跳变**（不是连续线性）。每词条前 6 档显式配置为 `min_x` 列表，第 7 档起按 `T(n)=T0×r^(n-1)` 无限延伸 |
| 共鸣（Resonance） | **跨词条的组合特效**：两条（或三条）词条同时激活且 X 各自达阈值时生效，共鸣本身也有 3 档（按两词条 X 之和超出部分判定） |
| 层数来源（Gain） | 层数的输入通道。除餐品特性外，事件、QTE、连击、优档成品、共鸣都能给层数，共 18 类规则 |
| 已激活词条 | 当前已满足门槛的词条集合。"所属已激活词条""随机已激活词条"的判定都基于这个集合 |

**限速三件套（替代层数上限）**：因为层数不封顶，控速全部落在"涨得多快"上 ——

```
单次触发所需销量  N(X) = N0 × (1 + X / G)      # X 越高，同样一份卖出去越不值
单餐品每日触发上限 K                            # 想继续涨就得换菜单、上更多款
阶梯阈值         T(n) = T0 × r^(n-1)           # 档位间距几何增长
```

有界量（概率、时间减免比例、满意度）用软上限收敛（概率 ≤95%、时间减免 ≤80%），无界量（利润、加购份数、层数）永不上限。

> 词条 = 玩家做"菜单构筑"的收益出口。**上架几款同属性餐品**决定激活，**卖多少份**决定层数 —— 这两条构成本作最主要的策略张力，详见 [03-备餐阶段](03-备餐阶段.md) 与 [04-出摊阶段](04-出摊阶段.md)。

### 3.4 空间与器具

| 词 | 单位 | 说明 |
|---|---|---|
| 台面格 | 格 | 摊位台面的容量单位。厨具、制作中的餐品占用台面格 |
| 储存格 | 格 | 库存容量单位，存放食材、半成品、成品 |
| 摊位空间 | 格 | `food.xlsx` 中每个餐品的固定占用值（0~6）。定义为**该餐品上架后常驻占用的台面格**；取 0 表示纯成品型（如可乐、汽水），不需要操作位 [假设-4] |
| 厨具 | `Utensil` | 锅、炸锅、制冰机、榨汁机、豆浆机、冰柜。加工食材必须占用对应厨具 |
| 无厨具可售成品 | bool | `food.xlsx` 字段。为「是」表示即使没有该厨具，也能直接拿现成成品售卖（不能从半成品开始加工）；为「否」表示没有厨具则该餐品无法上架 |
| 工位 | slot | 一件厨具同一时刻可处理的加工任务数，默认 1 [待定] |

### 3.5 食材与加工

食材阶段共 5 级，`stageIndex` 单调递增，**加工只能逐级推进，不能跳级**：

| stageIndex | 阶段 | ID | 说明 |
|---|---|---|---|
| 0 | 原料 | `RAW` | 天然原物料，如土豆、柠檬、大豆、芒果 |
| 1 | 食材 | `INGREDIENT` | 已选拣/洗净的基础食材，如蔬菜 |
| 2 | 生半成品 | `SEMI_RAW` | 如淀粉肠、火锅小料、鸡肉 |
| 3 | 熟半成品 | `SEMI_COOKED` | 如粉、调料、糖浆、椰奶 |
| 4 | 成品 | `FINISHED` | 唯一可售状态 |

- `food.xlsx` 的「食材1（种类/起始阶段/数量）」中的"起始阶段"= **该食材进货到手时的阶段**。写成 `成品` 的（方便面、汤、可乐）意味着买来即可售，不占加工时间。
- **原料与食材的边界**：现有数据里 `土豆/原料`、`柠檬/原料`、`蔬菜/食材` 并存，两条都出现在餐品配方里且都不需要额外前置动作。故二者视为**同层级的两种命名**（均为 `stageIndex ≤ 1` 的未加工物），逻辑上不做区分。[假设-5] 若后续想拆成"原料需先处理为食材"，只需在配置里加一条转换规则，不动代码结构。
- **`1=10` 写法**：鲜榨西瓜汁的「西瓜/原料/1=10」，按"单份需求 1 份、整批采购单位 10 份"理解，即该食材按 10 的倍数采购 [待定:确认]。

### 3.6 品质与口碑

| 词 | ID | 说明 |
|---|---|---|
| 风味 | `Freshness` | 0~1 的连续值，1 = 刚出锅。随"成品完成后经过的时间"单调下降 |
| 风味档 | `FreshTier` | 优 / 良 / 普 / 次 / 废，5 档，由风味值区间映射。**废档不可售，只能丢弃** [假设-6] |
| 评价 | `Rating` | 单个顾客的满意度分，0~5 星 |
| 口碑 | `Reputation` | 跨日累积的展示型指标，影响基础客流 |
| 当日评分 | `DailyScore` | 当日结算产出，决定次日客流系数与经验 |

### 3.7 经济

| 词 | 说明 |
|---|---|
| 现金 | 当日可用资金，跨日结转 |
| 基准价 | 某餐品/食材的参考市价，配置表字段，供应商在此基础上浮动 |
| 定价 | 玩家为餐品设定的售价 |
| 营业额 | 当日所有成交金额之和 |
| 利润 | 营业额 − 当日采购支出（含运费、临时采购溢价） |

## 4. 命名规范（给程序）

| 类型 | 规范 | 例 |
|---|---|---|
| 配置表 | `CFG_<实体>`，对应 `food.xlsx`/`buff.xlsx` 的一张 sheet | `CFG_Food`、`CFG_Trait`、`CFG_Utensil` |

| 加成 | `BUFF_<效果>` | `BUFF_SLOT_EXPAND` |
| 技能 | `SKILL_<分支>_<名称>` | `SKILL_EFF_PREP_FAST` |
