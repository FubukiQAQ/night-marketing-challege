# 01 核心循环与时间轴

> 《不烧心夜市挑战》策划案 · v0.1
> 上游：[00-术语表与约定](00-术语表与约定.md) ｜ 下游：[02-备货阶段](02-备货阶段.md)

本章定义**一回合（一天）的完整状态机**、三个阶段的时间货币、以及跨日结转的数据边界。所有阶段文档都是本章某一段的展开。

---

## 1. 一轮游戏的时间骨架

```
轮（Run）= 7 天
└─ 第 d 天（d = 1..7）
   ├─ 8:00-14:00  备货 STOCK   货币：分钟(360) / 现金
   ├─ 14:00-20:00 备餐 PREP    货币：分钟(360) / 台面格 / 现金
   ├─ 20:00-24:00 出摊 SELL    货币：游戏刻(12000) / 播放 60 实时秒
   ├─ 结算 SETTLE              评分 → 加成三选一
   └─ 次日 8:00 开盘（d < 7）
└─ 轮结算 RUN_SETTLE → 局外养成 META → 下一轮
```

**戏剧曲线**：备货是"资源受限下的信息决策"（供应商随机、需预测销量），备餐是"构筑与排产"（菜单=属性组合=词条激活），出摊是"实时执行与兑现"（60 秒内把准备变成钱）。三段各自有独立的失败点，所以每段的失败都不能直接把玩家打死 —— 见 §5。

## 2. 状态机

```
RUN_START
  └→ DAY_START(d)
       └→ STOCK ──(时间耗尽/玩家点"收工")→ PREP
            └→ PREP ──(时间耗尽/玩家点"出摊")→ SELL_READY
                 └→ SELL(12000 tick) ──→ SETTLE
                      └→ d<7 ? DAY_START(d+1) : RUN_SETTLE
                           └→ META ──(开局)──→ RUN_START
```

状态机约束：

| 规则 | 说明 |
|---|---|
| 单向前进 | 阶段不可回退。进 PREP 后不能再采购市场货（只能走"临时采购"），进 SELL 后菜单与定价锁死 |
| 提前结束 | 玩家可在任意阶段主动结束，未用完的分钟作废，不折算 |
| 强制推进 | 时间耗尽自动进入下一阶段，并给出提示 |
| 中断恢复 | 任一阶段可保存退出，重进原样恢复（存档结构见 [08](08-技术实现-Web.md)） |

### 2.1 阶段进入钩子

| 钩子 | 触发点 | 已挂载内容 |
|---|---|---|
| `onEnterStock` | 进入备货 | 刷新供应商池、结算昨日在线订单到货、应用备货阶段随机事件 |
| `onEnterPrep` | 进入备餐 | 计算各属性上架款数基线、按昨日销量生成建议进货/建议上架、激活本日天气修正 |
| `onEnterSell` | 进入出摊 | **触发所有「进入出摊阶段时」类餐品特性**（如炸鸡排：所有已激活词条层数 +1）；生成顾客到达序列；锁定菜单 |
| `onExitSell` | 出摊结束 | **触发所有「结束出摊阶段时」类特性**（如炸薯条：所有已激活词条层数 +1）；结算剩货风味 |
| `onSettle` | 结算 | 计算营业额、满意度、评分，发放经验 |

> 出摊前触发 / 出摊后触发的顺序差一拍，会导致同一条词条在出摊中有/无收益，这是数值表要卡的点，不是 Bug。

## 3. 时间货币分配

| 阶段 | 总量 | 计量单位 | 主要消耗点 | 耗尽后果 |
|---|---|---|---|---|
| 备货 | 360 min | 分钟 | 逛市场、比价、下单、搬运 | 强制进备餐，未买够就得靠临时采购 |
| 备餐 | 360 min | 分钟 | 改菜单、预加工、备成品、临时采购 | 强制出摊，未备的餐品到点做不出来 |
| 出摊 | 12000 tick | 游戏刻 | 出餐占用、顾客等待 | 打烊，剩货按规则处理 |

**关键换算**：`1 实时秒 = 200 tick`，出摊共 60 秒。加速观看不改变 tick 数，只改变每 tick 的实时时长（默认 1x，可 2x，仍跑满 12000 tick）。

时间作为**核心稀缺资源**的三条设计约束：

1. 备货的"现场采购"吃分钟、省钱；"在线订货"省分钟、加运费且 T+1 —— 这是全局第一个权衡。
2. 备餐的"预加工"把时间从出摊挪到备餐，但成品会掉风味 —— 第二个权衡。
3. 出摊的每分钟只能做有限几份 —— 前两段省下来的时间在第三段变成钱，玩家必须能感知这条因果链。UI 必须同时显示"我还剩多少分钟"和"我的招牌菜做一份要多久"。

## 4. 跨日结转（哪些数据活着，哪些每天重置）

| 数据 | 结转 | 说明 |
|---|---|---|
| 现金 | ✅ 每日结转 | 可负？否，最低 0 [假设-7] |
| 食材 / 半成品库存 | ✅ | 受储存格限制 |
| 成品库存 | ⚠️ 最多 1 天 | 隔夜后风味继续下降，超过 1 天强制丢弃 |
| 菜单与定价 | ✅ 保留为默认 | 玩家可直接"照旧出摊" |
| 口碑 / 昨日评分 | ✅ | 昨日评分 → 今日客流，见 [05](05-评分与养成.md) |
| 词条层数 X | ✅ **永久累积** | 跨日、跨轮都保留，只增不减；控速靠"触发所需销量随 X 增长"与"单餐品每日触发上限" [假设-18] |
| 已激活词条 | ❌ 每日重算 | 由当日菜单的上架款数决定，所以层数虽在，今天不点这条属性就用不出来 |
| 共鸣状态 | ❌ 每日重算 | 依赖"两条词条同时激活"，随菜单走 |
| 已购厨具 | ✅ | 局外解锁，永久 |
| 台面格 / 储存格 | ✅ | 由加成扩容累积 |
| 未到货的在线订单 | ✅ | T+1 到货，隔日必须送达（除非被事件拦截） |
| 随机事件 buff（跨日型） | ⚠️ 按事件自带的持续天数 | |

> **层数永久累积**是本作的长期曲线：玩家每一轮都在变强，但"今天哪条词条能生效"仍然要每天靠菜单重新争取。所以节奏压力全部压在**激活门槛**上，而不是层数上 —— 想用上已经养大的词条，今天就必须上架够款数，而台面格又不够。改这条之前务必回到 [10](10-待确认项与假设.md) 讨论。

## 5. 失败与压力（不设硬死）

| 情形 | 处理 |
|---|---|
| 现金无法支付最低采购 | 进入"赊账"：可采购但当日结算时先扣利息 `[待定:5%~10%]`，或降级接受质量更差的货 [假设-7] |
| 单日评分极低 | 不判定失败，但次日基础客流按 [05](05-评分与养成.md) 的系数下降，形成负螺旋 |
| 连续 3 天评分低于 `[待定]` | 触发"摊主危机"事件：给一次强力补救（一次性大幅加成 or 贷款），不结束游戏 |
| 7 天结束 | 无论经营好坏都结算经验，经验按评分曲线给出 —— 差局也给得起至少 1 个技能点，保证养成不退步 |

设计意图：增量类游戏的正反馈必须压过挫败。宁可让玩家"这局赚得少"，也不要让玩家"这局废了"。

## 6. 一天的完整流程（玩家视角）

1. **开盘**：看到昨日总结卡（营业额、评分、差评原因、剩货清单、今日常客需求倾向）。
2. **备货**：翻 3~5 家供应商，比价下单，观察当日事件（某供应商停业/某食材涨价/物流受阻）。
3. **备餐**：调菜单 → 实时看到"速食 3 款 = 速度为王激活""还差 2 款到二档" → 定价 → 排产预加工 → 确认台面格没超。
4. **出摊**：60 秒实时，看顾客排队、点单、出餐、飘字涨层数，处理特殊顾客 QTE。
5. **结算**：营业额 / 满意度 / 评分逐条弹出 → 三选一加成。
6. **次日**：回到 1。

## 7. 引导节奏（7 天教学曲线）

| 天 | 新解锁 | 教学重点 |
|---|---|---|
| 1 | 备货现场采购 + 2 个餐品 + 单厨具 | 只教"买 → 做 → 卖"最小闭环，不出事件 |
| 2 | 在线订货 | 教运费 vs 时间的权衡，教学日必定有"次日到货"提示 |
| 3 | 词条系统（属性/上架款数/层数） | 强制上架 3 款速食，让玩家亲眼看到第 3 款激活瞬间 |
| 4 | 定价与风味衰减 | 给一个必须提前备货的爆款，教"做早了会掉风味" |
| 5 | 特殊顾客 QTE | 首次 QTE 宽容失败 |
| 6 | 台面容量吃紧 + 第二厨具 | 教空间取舍 |
| 7 | 全开 + 一次大型事件 | 结算演出 |

具体数值（每天给多少钱、多少格）全部 `[待定]`，但**解锁顺序**与教学目标是确定的。
