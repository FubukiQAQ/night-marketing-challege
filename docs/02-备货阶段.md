# 02 备货阶段

> 《不烧心夜市挑战》策划案 · v0.1
> 上游：[01-核心循环与时间轴](01-核心循环与时间轴.md) ｜ 下游：[03-备餐阶段](03-备餐阶段.md)

**时段** 8:00-14:00 ｜ **时间预算** 360 分钟 ｜ **货币** 分钟 + 现金 ｜ **产出** 今日库存（食材/半成品/成品）+ 未到货的在线订单

本章要解决的问题：**在信息不完整（供应商随机）和时间有限（360 分钟）的前提下，把现金换成正确种类、正确数量的食材。**

---

## 1. 阶段流程

```
进入备货
 ├─ 结算昨日在线订单（T+1 到货）        ← 可能被事件拦截
 ├─ 触发生成今日供应商池（3~5 家营业）
 ├─ 触发备货阶段随机事件
 └─ 玩家自由行动（可循环，直到时间耗尽或主动结束）
      ├─ 逛供应商 → 比价 → 现场采购（消耗分钟，价格低）
      ├─ 在线订货（不消耗分钟，付运费，次日到）
      ├─ 查看昨日销售/缺货复盘
      └─ 放弃采购直接进备餐
```

---

## 2. 供应商系统

### 2.1 供应商属性

| 字段 | 说明 |
|---|---|
| 名称 | 展示用，如「老张蔬菜批发」「海鲜老李」 |
| 主营品类 | 决定其 SKU 池（蔬菜 / 肉类 / 主食 / 调料 / 包装饮料 …） |
| 加价率 | 相对基准价的溢价区间 `[待定: -10% ~ +25%]`，不同供应商稳定不同，构成比价意义 |
| 库存量 | 每个 SKU 当日可买上限 `[待定]` |
| 营业概率 | 每日营业的基础概率 `[待定]`，受事件修正 |
| 运费规则 | 在线订货时的运费计算参数 |
| 关系度 | 跨日累积：累计交易额达标后加价率下降 / 解锁稀有 SKU `[待定]` |

### 2.2 每日刷新规则

1. 每天开盘从供应商总表按 `营业概率 × 事件修正` 抽取 **3~5 家**营业。
2. 每家从自己的 SKU 池随机抽 **4~8 个** 在售货品 —— 同一家供应商每天卖什么不一样，这是"多找找有没有想买的"的实现。
3. 每个 SKU 的单价 = `基准价 × (1 + 供应商加价率) × (1 + 当日随机波动)`，随机波动 `[待定: ±15%]`。
4. 每个 SKU 的库存 = `基础库存 × 随机系数` `[待定]`，售完即止。
5. 稀有货品（如某些只在特定供应商出现的食材）出现概率 `[待定]`，可被事件强制上架。

> **设计意图**：随机不是为了折磨玩家，而是为了让"每天重新规划菜单"成为必要。若某天市场缺主力食材，玩家必须临场换菜 —— 换菜就会改变属性组合，进而改变词条激活，形成当天的分支剧情。

### 2.3 供应商相关随机事件

| 事件 | 效果 |
|---|---|
| 供应商停业 | 该供应商当天不可用 |
| 涨价潮 | 某品类全线 +`[待定]`% |
| 清仓甩卖 | 某供应商全部 SKU −`[待定]`%，库存翻倍 |
| 物流受阻 | 今日所有在线订单延迟到 T+2 |
| 新供应商入场 | 额外增加一家高加价率但稀有货齐全的供应商 |
| 缺货 | 某 SKU 库存归零 |

完整事件表见 [06-随机事件与QTE](06-随机事件与QTE.md)。

## 3. 两条采购通道

| 维度 | 现场采购 | 在线订货 |
|---|---|---|
| 时间成本 | 逛店 + 下单消耗**分钟** | 0 分钟 |
| 金钱成本 | 基准价，无运费 | 基准价 + 运费 |
| 到手时间 | 立即入库 | T+1（次日 8:00 到货） |
| 选品丰富度 | 完整 SKU 池 | 只有标了"支持配送"的 SKU，通常更少 [待定] |
| 风险 | 无 | 缺货/延迟/被事件拦截 |
| 用途 | 今天就要用的东西 | 明天要用的、量大笨重的东西 |

### 3.1 现场采购的时间账

| 动作 | 耗时 |
|---|---|
| 前往一个新的供应商（本日首次） | `[待定: 20~40]` min |
| 再次前往同一供应商 | `[待定: 5~15]` min |
| 浏览货架 | 0 |
| 下单成交（每笔） | `[待定: 5]` min |
| 采购大批量（超过 `[待定]` 件） | 额外 `[待定]` min |
| 返回摊位（结束备货前最后一次） | `[待定: 15]` min |

- 首次访问耗时高 → 玩家必须决定"今天去几家"，天然限制信息量。
- 时间归零时若人在市场，自动返回摊位并进入备餐。

### 3.2 在线订货的运费

```
运费 = 基础运费[待定] + Σ(单件重量[待定] × 件数) × 重量费率[待定] × (1 + 事件修正)
```

- 运费与小计合并显示，让玩家直观看到"省 30 分钟 = 多花 X 元"。
- 订单在下单瞬间扣款；T+1 到货时若储存格不够，**超出部分丢失并警告**（不退款）。
- 允许"催单"：额外付费 `[待定]` 让今日订单当日送达，概率失败 `[待定]`。

## 4. 库存与储存格

- 所有采购品进入**储存格**，占格数按食材种类计 `[待定: 1 格/ N 份]`。
- 储存格不足时：禁止超额下单（UI 直接灰掉），或允许"堆在摊外"并付出品质下降代价 `[待定]`。
- 已到手食材不会腐败（只有**成品**会掉风味），这是刻意的简化：把复杂度压到出摊阶段 [假设-9]。

---

## 5. 复盘面板（本阶段的决策依据）

备货界面常驻一个「昨日复盘」抽屉，必须包含：

| 区块 | 内容 |
|---|---|
| 昨日营业额 / 评分 | 与 7 天均值对比，箭头表示趋势 |
| 单品销量榜 | 按份数排序，标注"因缺货损失"的次数 |
| 缺货告警 | 哪些餐品被点了但做不出 → **优先级最高**的进货依据 |
| 剩货清单 | 昨日没卖完的成品及其风味档，提示今日是否还可用 |
| 建议进货量 | `建议量 = 昨日销量 × 天气系数 × 客流系数 − 现有库存`，向上取整，仅作参考可一键填入 |
| 今日特殊信号 | 如"附近有夜市活动，客流 +X%" |

## 6. 事件钩子

| 钩子 | 时机 |
|---|---|
| 订单到货 | onEnterStock 最前 |

| 跨日型影响 | 在次日开盘统一结算 |
