# 04 出摊阶段

> 《不烧心夜市挑战》策划案 · v0.1
> 上游：[03-备餐阶段](03-备餐阶段.md) ｜ 下游：[05-评分与养成](05-评分与养成.md)

**时段** 20:00-24:00 ｜ **长度** 12000 tick = 60 实时秒（200 tick/s） ｜ **货币** 游戏刻 ｜ **产出** 营业额、顾客评价、词条层数、剩货

这一段是"兑现"：前两段的所有决策在这里被压缩成 60 秒的实时演出。玩家不能改菜单、不能改价，只能**看、反应、处理特殊顾客**。

---

## 1. 时间换算表（全文通用）

| tick | 实时秒 | 店内时间 | 典型含义 |
|---|---|---|---|
| 1 | 0.005 | 1.2 秒 | 模拟步长 |
| 10 | 0.05 | 12 秒 | 最快出餐（炸薯条 10 tick） |
| 20 | 0.1 | 24 秒 | 饮品出餐 |
| 50 | 0.25 | 1 分钟 | 方便面/炸鸡排出餐 |
| 100 | 0.5 | 2 分钟 | 酸辣粉/炸全鸡出餐 |
| 300 | 1.5 | 6 分钟 | 顾客耐心下限 `[待定]` |
| 12000 | 60 | 4 小时 | 全场总长 |

> 换算基准 `1 tick = 1.2 游戏秒` 的依据：让 `50 tick` 正好是店内 1 分钟，与 `food.xlsx` 的出餐时间取值吻合。见 [假设-2]。

## 2. 出摊主循环（伪代码）

```
for tick in 1..12000:
    推进 风味衰减(所有成品)
    推进 顾客到达(λ(tick))     → 生成新顾客、入队
    推进 顾客状态机             → 点单 / 等待 / 出餐 / 离开
    推进 厨具加工队列           → 完成出餐、交付
    触发 词条层数增长与效果     → 飘字反馈
    判定 随机事件 / QTE 弹出
    推进 画面表现（渲染按帧插值，与 tick 解耦）
结算 → 剩货处理 → 评分
```

逻辑（tick）与表现（帧）严格分离：`1x` 时 1 tick ≈ 5 ms 实时，`2x` 时可压到 2.5 ms，但**模拟结果的 tick 序列必须完全一致**（确定性，见 [08](08-技术实现-Web.md)）。

## 3. 客流模型

### 3.1 到达强度

```
客流强度 λ(t) = 基础客流 × 曲线(t) × 评分修正 × 口碑修正 × 定价修正 × 事件修正
```

| 因子 | 口径 |
|---|---|
| 基础客流 | 由天数难度曲线给出 `[待定]`（第 1 天最低，第 7 天最高） |
| 曲线(t) | 把 12000 tick 切成若干时段，各时段权重不同。夜市典型形态：20:00-21:00 爬升、21:00-22:30 峰值、22:30-24:00 长尾。权重表 `[待定]` |
| 评分修正 | 昨日评分 → 系数，映射见 [05](05-评分与养成.md) §2 |
| 口碑修正 | 跨日累积，斜率较缓 |
| 定价修正 | 见 [03](03-备餐阶段.md) §6 的弹性式 |
| 事件修正 | 「同行竞争 −X%」「夜市活动 +X%」等 |

到达过程用**泊松过程**离散化：每 tick 的到达概率 = `λ(t) / 200`（因为 1 秒 = 200 tick）。同屏队列上限 `[待定]`，超出的顾客直接流失（记为"没排上队"）。

### 3.2 顾客属性

| 字段 | 说明 |
|---|---|
| 需求偏好 | 按当前菜单的**属性**加权抽取（不是按餐品），决定他"想吃什么"。这让属性系统在需求端也发挥作用 |
| 备选容忍度 | 首选餐品售罄时，是否愿意换同类其它餐品。概率 `[待定]` |
| 预算 | 单客消费上限 `[待定]`，超过则不买 |
| 耐心 | 等待上限 `[待定: 300~900]` tick，超时离开并给出负面评价 |
| 加购倾向 | 受「吃饱了」「好辣！」等词条放大，见 §5 |
| 特殊顾客标记 | 触发 QTE，见 [06](06-随机事件与QTE.md) |

### 3.3 顾客状态机

```
ARRIVED → BROWSE(选品) → ORDER(下单) → WAIT(等出餐) → EAT(评价生成) → LEFT
                                    ↘ ABANDON(耐心耗尽/售罄/预算不足) → LEFT
```

- `BROWSE` 耗时 `[待定: 40~120]` tick，用来制造队列节奏。
- `WAIT` 期间随时间降低满意度：`满意度 = 初始满意度 − 耐心衰减系数 × 已等待 tick`。
- 若某顾客点的餐品全部售罄且拒绝替换 → `ABANDON`，记为一次"缺货流失"，会拉低评分（缺货是最容易改进的差评来源，UI 要单独统计）。

## 4. 出餐与厨具排队

### 4.1 出餐时间

```
出餐耗时(餐品) = D(餐品) × Π(1 + 词条修正) × (1 + 拥堵惩罚[待定])
```

- `D` 取自 `food.xlsx` 的「出餐时间/游戏刻」（0 / 10 / 20 / 30 / 50 / 100）。
- **已预加工为成品**的餐品：`D_实际 = D_take[待定: 5]` tick（取货即交），风味按当前值结算。
- **未加工到成品**的餐品：走完整 `D`，并且**占用对应厨具**。
- 词条修正：
  - 速度为王（速食）一档：速食餐品 −20%
  - 速度为王 二档：**所有**餐品 −20%
  - 现做饮品（现做饮品）：−`(20 + X)%`

### 4.2 厨具排队

- 每件厨具 1 个工位 [假设-11]，同一时刻只能做 1 份，其余按 FIFO 排队。
- **同一件厨具排队过长是掉单主因**。设计上希望玩家在第 4 天后主动"分厨具"（锅+炸锅并行）而不是全押一口锅。
- 不需要厨具的餐品（可乐、汽水）不排队，立即交付 —— 它们是**保底客流吞吐**。
- 拥堵惩罚：当某厨具队列长度 ≥ `[待定]` 时，该队列出餐时间乘以 `[待定: 1.1~1.5]`，用来惩罚"单品爆款+单厨具"的极端构筑，也让多品类菜单更有价值。

### 4.3 冰冰冰的特殊通道

词条「冰冰冰」激活后，凉菜类餐品**无需成品即可交付**：直接扣食谱中的食材库存，`D_实际 = D_take`。
实现上是给该属性的餐品开一条 `bypass_finished` 通道；若食材不足则该份不可售。

## 5. 词条层数：出摊阶段的核心爽点

### 5.1 层数的来源（`配表/TraitGain`，18 类规则）

| 来源 | 例子 | 实现口径 |
|---|---|---|
| 按销量计数 | 方便面「每售出 8 份，所属已激活词条 +1」 | 计数器累加，达 `N(X)` 结算一次 |
| 概率触发 | 火鸡面「每售出 1 份，10% 概率 +1」 | 每份独立判定 |
| 按营业额 | 大件餐品每满 30 元 +1 | 适合炸全鸡这类高单价 |
| 阶段钩子 | 炸鸡排「进入出摊时全摊 +1」/ 炸薯条「结束出摊时全摊 +1」 | 见 [01](01-核心循环与时间轴.md) §2.1 |
| 首次售出 | 饮品「当日首次售出时层数最高 +5」 | 可带空间条件（`space_gte:4`） |
| 连击 streak | 连续同属性成交达上限给层数 | 上限由「炭火气」词条抬高 |
| QTE / 特殊顾客 / 事件 | 成功给、失败不给 | 全局通道，单日有上限 |
| 优档成品 | 售出「优」档成品额外 +1 | 奖励新鲜度管理 |
| 共鸣 | 共鸣激活时给指定词条 | 见 §5.4 |

**"所属"的解释**：指该餐品自身拥有且当前已激活的全部词条（如酸辣粉同时给「魔鬼辣」「现做食品」「主食」+1）[假设-12]。另有 `random_active`（随机一条已激活）、`highest`/`lowest`（层数最高/最低的一条）、`own_tag_noreq`（所属词条，无需激活）等目标口径。

### 5.1.1 不封顶，但涨得越来越慢

层数**永久累积、跨日跨轮保留**（[假设-18]），所以控速不靠上限，靠三条硬规则（`配表/Balance`）：

```
N(X) = N0 × (1 + X / G)      # N0=8 份，G=120 层：X=0 时 8 份涨 1；X=120 时 16 份涨 1
每日触发上限 K = 6 次/餐品     # 想继续涨就得换菜单、上更多款
档位阈值 T(n) = T0 × r^(n-1)  # r=1.35，档位越来越难摸到
```

合起来的效果：早期一天涨几层就够花，中期要靠拓宽菜单维持速度，后期必须靠共鸣和更多属性同时推进。玩家不会被"满了"卡住，也不会线性变强。

### 5.4 共鸣在出摊里怎么表现

- 触发瞬间：摊位上方亮起组合名（如「解辣搭档」），之后常驻在词条条最右端。
- 生效方式：给该组合指定的一类成交加效果（加购、客单价、份数上限、利润）。
- 档位：按两词条 X 之和超出阈值的部分分 3 档（`配表/ResonanceTier`，阈值 0/30/80）。
- 消失条件：**当天菜单不再满足"两条都激活"时共鸣消失**。层数本身不会掉，掉的是共鸣的成立条件。

### 5.2 层数的实时反馈（必须做）

每层数变化都要有**可感知的即时反馈**：

- 摊位上对应的词条图标闪一下 + `+1` 飘字
- 侧边词条条显示的 `X` 数字滚动增加
- 触发档位效果时（如好辣！多卖了一份饮料）单独飘一条 `加购！`
- 升档时全屏横幅：`速度为王 二档！`
- 结算时列出"本次贡献最多的三条词条"

增量游戏的核心快感来自"数字在涨"，如果层数在后台悄悄累加，整个系统等于不存在。

## 6. 风味衰减

```
风味(成品, t) = clamp( 1 − k × 已放置游戏分钟 × (1 − 冷藏修正), 0, 1 )
```

| 项 | 说明 |
|---|---|
| 已放置游戏分钟 | 从"制作完成"起算，跨越备餐尾段 + 出摊全程 |
| k | 每分钟衰减率 `[待定]`，不同品类可不同（凉菜慢、炸货快、饮品中） |
| 冷藏修正 | 冰柜中存放的成品衰减更慢 `[待定: 0.5]` |
| 档位映射 | 优 `[0.9, 1]` / 良 `[0.7, 0.9)` / 普 `[0.5, 0.7)` / 次 `[0.25, 0.5)` / 废 `[0, 0.25)` `[待定]` |

影响：
- 售价系数 `售价实际 = 定价 × 风味档系数`（优 1.0 / 良 0.9 / 普 0.8 / 次 0.6 / 废 0）
- 顾客评价：次档 −1 星，废档直接拒收并记差评
- **废档不可售**，只能丢

> 这一条是"全部预加工"策略的唯一刹车。没有它，最优解永远是提前把一切做成成品。

## 7. 出摊期间的随机事件与 QTE

| 类型 | 例子 | 处理 |
|---|---|---|
| 客流型 | 团购订单（一批顾客同时到）、夜市活动 | 立刻改变 λ(t) |
| 竞争型 | 隔壁开了同行摊位，某属性需求下降 | 修改需求权重 |
| 供给型 | 突然断货、厨具故障（少一个工位） | 修改产能 |
| 特殊顾客 | 美食博主、大胃王、挑剔老人、催单外卖员 | 弹 QTE，成功给大额收益，失败有惩罚 |

事件与 QTE 的完整设计见 [06-随机事件与QTE](06-随机事件与QTE.md)。约束：**一局出摊最多弹出 `[待定: 3]` 个 QTE**，避免 60 秒被打断得支离破碎。

## 8. 打烊与剩货处理

出摊结束（tick = 12000）后：

| 选择 | 效果 |
|---|---|
| 丢弃 | 成本全亏，无后续影响 |
| 保留 | 进入次日库存，风味继续按跨夜规则下降；**最多保留 1 天**，第 2 天开盘强制丢弃 |

- 保留的价值：次日可少做一部分，节省备餐分钟。
- 保留的风险：次日开局的成品多半已掉到"次"档，卖相与评价都差。
- UI 需给出"留到明天还能卖 X 元"的预估，让选择可算。

## 9. 当日结算

```
成交客数 N、成交份数 U、营业额 R = Σ(成交单价)
客单价 = R / N
满意度 S = Σ(单客评价星级) / N
客诉率 C = 差评数 / N
缺货流失率 L = 缺货离开客数 / 到店客数

评分 = w1 × min(1, R / 目标营业额)
     + w2 × (S / 5)
     − w3 × C
     − w4 × L
     映射到 0~100 分（或 1~5 星，展示口径 [待定]）
```

- `目标营业额 = 基础目标(天数) × (1 + 口碑加成) × 台面容量系数` `[待定]`
- 权重 `w1..w4` `[待定]`，建议 `w1` 不高于 0.6，保证"评价差但赚得多"拿不到高分。
- 评分输出三件事：次日客流系数、今日经验、可用于展示的等级（见 [05](05-评分与养成.md)）。

结算演出顺序：营业额滚动 → 订单流水 → 词条贡献榜 → 满意度/差评原因 → 评分 → 加成三选一。整段 `[待定: 8~15]` 秒，可点击跳过。

## 10. 表现层要求（给美术/前端）

| 要素 | 要求 |
|---|---|
| 视角 | 2D 侧视或俯视固定摊位，餐品与顾客用可辨识的小图标 |
| 摊位忙碌感 | 同时在做几份、哪口锅在冒气、队列长度，观众要能一眼看出"我在爆单"还是"我在干等" |
| 顾客表现 | 排队队列可视化、耐心条（低于 30% 变红）、离开时的情绪符号 |
| 飘字 | 金额、层数 +1、加购、差评，四类用不同颜色与字号 |
| 加速 | 1x / 2x 切换，不影响模拟结果 |
| 音效锚点 | 出餐成功、层数提升、QTE 出现、打烊铃 |
