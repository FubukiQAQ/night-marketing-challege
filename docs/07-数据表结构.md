> **权威数据已交付**：`配表/不烧心夜市-配表.xlsx`（13 个 sheet）+ `配表/csv/` 逐表 CSV + `配表/校验报告.md`。
> 本章是**字段字典与导出规范**，与配表一一对应；`food.xlsx` / `buff.xlsx` 已降级为历史留档，只读不改。

导出原则：

1. 一个 sheet 一张配置表，一行一条记录，首行表头用英文 `snake_case`（列名同时给中文注释，见配表）。
2. 数值标注「待校」表示 v0 骨架，允许改；结构字段不允许随手改名（会打断引用）。
3. 生成链：`tools/tbl_data_*.py`（策划可读的数据源） → `tools/build_tables.py` → xlsx + csv + 校验报告。改数只需改数据源再重跑一条命令，避免手改 xlsx 造成各处不一致。

## 4. `CFG_Trait` 词条表（由 `buff.xlsx` 结构化）

| 字段 | 类型 | 说明 | 现有数据 |
|---|---|---|---|
| `trait_id` | string | `fastest` / `full` / `spicy` / `madedrink` / `madefood` / `iceice` | ✅ 由「词条名称」映射 |
| `name` | string | 速度为王 / 吃饱了 / 好辣！ / 现做饮品 / 现做的不烧心 / 冰冰冰 | ✅ |
| `tag_id` | string | 绑定的属性 | ✅ 从效果文本推断 |
| `stackable` | bool | 是否可叠加层数 | ✅ 「是否可叠加层数」 |
| `layer_cap` | int | 层数上限（不可叠加时 = 1） | ✅ 推导 |
| `unlock_menu_count` | int | 一档激活所需上架款数 | ✅ 3/3/4/6/4/6 |
| `upgrade_menu_count` | int | 二档所需上架款数（无二档填 null） | ✅ 5/5/null/null/null/null |
| `effect_type` | enum | `time_reduce` / `extra_buy` / `profit_up` / `bypass_finished` | 由效果文本归类 |
| `effect_scope` | enum | `self_tag`（仅该属性餐品）/ `all_food`（全餐品） | 速度为王二档为 `all_food` |
| `effect_formula` | string | 结构化公式，如 `-(20+X)%` | 由自然语言转写 |
| `effect_desc` | string | 展示文案（保留原文） | ✅ |
| `layer_gain_baseline` | int | 设计上"常规一局可达层数"基线，用于校验 | `[待定]` |

规则口径（写进公式解析器，见 [08](08-技术实现-Web.md)）：

- `X` = 当前层数，`X=0` 表示未激活，不产生任何效果。
- `stackable=false` 时 `X ∈ {0,1}`。
- 效果作用对象与"上架款数门槛"是两个独立维度：速度为王一档只作用于速食，二档作用于全部餐品。

## 13. 导出与校验流程

1. 策划维护 `xlsx`（`food.xlsx`、`buff.xlsx` 及新增表，建议合并为一个工作簿多 sheet，或保持多文件 + 清单）。
2. 构建脚本 `tools/xlsx2json.py`：读表 → 校验 → 输出 `src/data/*.json`。
3. 校验项（不通过则构建失败）：
   - 必填字段非空（允许标了 `@todo` 的数值字段为空）
   - `tag_ids` 中的 ID 必须存在于 `CFG_Tag`
   - `ingredient_id` 必须存在于 `CFG_Ingredient`；`start_stage` 必须在 `stage_chain` 中
   - `utensil_id` 必须存在于 `CFG_Utensil`
   - 数值范围：`space ≥ 0`、`serve_time_ticks ≥ 0`、概率 `∈ [0,1]`
   - 引用完整性：事件 `effects` 里的 `target` 必须能解析
4. 导出的 JSON 带 `version` 与源文件哈希，便于排查"改了表没生效"。
