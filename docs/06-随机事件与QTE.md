# 06 随机事件与 QTE

> 《不烧心夜市挑战》策划案 · v0.1
> 上游：[01-核心循环与时间轴](01-核心循环与时间轴.md) ｜ 关联：[02](02-备货阶段.md)、[04](04-出摊阶段.md)

随机事件是"每天的题不一样"的来源；QTE 是玩家在 60 秒出摊里**唯一的手**。

设计原则：**事件改参数，不改规则。** 任何事件都不能让玩家做已经锁定的操作（比如出摊中改菜单），只能加减系数、开关产能、塞额外顾客。

---

## 1. 事件数据模型

```jsonc
{
  "id": "EVT_STOCK_SUPPLIER_CLOSED",
  "name": "供应商停业",
  "phase": "STOCK",              // STOCK | PREP | SELL | CROSS_DAY
  "timing": "ON_ENTER",          // ON_ENTER | ON_ACTION | ON_TICK | ON_EXIT
  "cond": { "minDay": 2, "requireTag": null },
  "weight": 10,                  // 相对权重，同组内归一
  "group": "SUPPLY",             // 同组事件互斥，避免同类连发
  "cooldownDays": 2,             // 连续多日不再触发
  "duration": 1,                 // 持续天数，0 = 即时
  "maxPerRun": 2,
  "effects": [
    { "op": "supplier.close", "target": "random", "count": 1 }
  ],
  "ui": { "icon": "shop_closed", "title": "老张蔬菜批发今日停业",
          "desc": "门口贴了张纸，说进货的车在路上坏了。" }
}
```

事件文案必须写**人话**，且与数值效果一致（说"涨价"，玩家就该看到价格数字真的变了）。

## 2. 效果指令集（op 表）

| op | 参数 | 作用 |
|---|---|---|
| `rate.set` | `var, value, duration` | 设置某个系数（客流、需求权重、出餐时间…） |
| `rate.mul` | `var, factor, duration` | 乘算修正 |
| `amount.add` | `target, value` | 加钱/加时间/加容量 |
| `supplier.close` | `target, count` | 关闭供应商 |
| `supplier.price` | `category, factor` | 某品类价格 ×factor |
| `supplier.stock` | `supplier, factor` | 库存 ×factor |
| `order.delay` | `days` | 在线订单延后 N 天 |
| `item.grant` | `ingredient, qty` | 白送食材（"邻居送了一筐菜"） |
| `item.spoil` | `ingredient, ratio` | 损坏库存 |
| `demand.tag` | `tag, factor` | 某属性需求权重变动 |
| `queue.cap` | `utensil, delta` | 厨具工位增减（故障/−1） |
| `spawn.group` | `tag, count, window` | 团购：窗口期内塞入 count 个该属性顾客 |
| `score.bonus` | `value` | 直接给评分加减 |
| `qte.trigger` | `qteId` | 触发 QTE |

新增 op 必须回本章登记。

## 3. 备货阶段事件

| 事件 | 效果 | 权重档 |
|---|---|---|
| 供应商停业 | 随机关 1 家 | 中 |
| 涨价潮 | 某品类全线 +`[待定]`% | 中 |
| 清仓甩卖 | 某家全品 −`[待定]`%，库存 ×2 | 低（好事） |
| 物流受阻 | 今日在线订单 → T+2 | 低 |
| 新供应商入场 | 额外 1 家稀有货齐全、加价高 | 低（好事） |
| 平台促销 | 运费全免今日 | 低（好事） |
| 天气突变（雨） | 今日全客流 −`[待定]`%，但堂食变外卖（单价 +`[待定]`） | 中，跨阶段生效 |
| 邻居送菜 | 白送某食材 `[待定]` 份 | 低（好事） |
| 冷库故障 | 损失 `[待定]`% 现有食材 | 低 |

好事与坏事的权重比例目标 **4 : 6** 左右 —— 玩家对坏事的记忆更重，实际体感会偏向"运气不好"，所以好事要略多。

## 4. 备餐阶段事件

原稿明确"无专属随机事件，但受备货事件影响"。本章遵守这条，只允许两类：

1. **备货事件的延续**（跨阶段持续），例如"天气突变"在备餐阶段继续影响预计客流。
2. **备餐阶段的玩家侧事件**（非随机）：临时采购渠道开放/关闭、供应商补货车到货（把昨天没买到的货上架） —— 由系统状态触发，权重 0。

理由：备餐是纯决策阶段，随机打断会破坏"我在做计划"的心流。

## 5. 出摊阶段事件

| 事件 | 效果 | 表现 |
|---|---|---|
| 团购订单 | 30 秒内额外塞入 `[待定]` 个同属性顾客 | 一队人走过来 |
| 同行竞争 | 某属性需求 −`[待定]`%，或整体客流 −`[待定]`% | 对面支起了摊子 |
| 夜市活动 | 客流 +`[待定]`% | 远处灯牌亮起 |
| 厨具故障 | 某厨具工位 −1 持续到打烊 | 冒黑烟 |
| 断货 | 某食材库存清零 | — |
| 醉酒闹事 | 短暂掉客流 + 需 QTE 处理 | 特殊顾客 |
| 城管巡查 | 全部出餐速度 −`[待定]`% 一段时间（要收敛动作） | 手电筒 |
| 偶遇老客 | 一次性满意度 +`[待定]` | 熟脸 |

出摊事件**上限**：一局最多 `[待定: 4]` 个，且两个事件的间隔 ≥ `[待定: 1500]` tick。60 秒里塞 6 个事件等于没有事件。

## 6. QTE 设计

### 6.1 通用规则

| 项 | 规则 |
|---|---|
| 弹出 | 特殊顾客出现时全屏短暂演出 + 单个操作面板，**暂停不暂停模拟？→ 暂停该顾客相关队列，其余继续** [假设-15] |
| 窗口 | 操作窗口 `[待定: 2.0~3.5]` 实时秒（`[待定]` tick 等价），显示倒计时环 |
| 次数 | 一局最多 `[待定: 3]` 个 QTE |
| 难度 | 随天数上升：窗口变短、目标值变高 `[待定]` |
| 失败 | 必给惩罚，但**分级**且可被养成减免 |
| 成功 | 必给**可感知的正反馈**（钱 + 飘字 + 顾客表情） |

### 6.2 四类 QTE

**A. 连点/蓄力 —— "催单"**
- 场景：外卖员催单。
- 玩法：`[待定: 2.5]` 秒内点到 `[待定: 12]` 次。
- 成功：该单金额 ×`[待定: 2]`，顾客评价 +1。
- 失败：赔款 `[待定]`，顾客评价 −1。

**B. 节奏 —— "颠勺/翻炸"**
- 场景：炸货需要掌握火候。
- 玩法：在 3 个节奏点上按到判定区（滑动/点击），命中数决定结果。
- 成功：本批炸货风味 +`[待定]`（相当于延后衰减）。
- 失败：本批炸货风味直接跌一档。

**C. 限时选择 —— "推荐"**
- 场景：美食博主问"你家最推荐什么？"
- 玩法：`[待定: 3]` 秒内从 3~4 个餐品中选一个。**正确答案 = 当前库存最多且风味档最高的餐品**，选项随机打乱。
- 成功：口碑 +`[待定]`，次日客流 +`[待定]`%。
- 失败：博主给了中评，今日满意度 −`[待定]`。

**D. 计算 —— "找零/算账"**
- 场景：顾客给大钞要找零。
- 玩法：限时输入正确找零金额（数字键盘）或从 4 个选项中选。
- 成功：正常成交 + 小费 `[待定]`。
- 失败：多找了钱（扣钱）或算错导致差评。

> 四类轮流出现，同一局不重复同一类型 [假设-16]，保证 60 秒内的操作有变化。

### 6.3 特殊顾客类型

| 顾客 | 触发 QTE | 强度 |
|---|---|---|
| 外卖员 | A 催单 | 常见 |
| 炸货老饕 | B 火候 | 中 |
| 美食博主 | C 推荐 | 稀有，收益最大 |
| 挑剔老人 | C/D 变体 | 中，失败惩罚偏评价 |
| 大胃王 | 连续出餐挑战（非 QTE，改成"10 秒内交出 N 份"） | 稀有 |
| 醉酒客 | 需 A+B 组合处理 | 中，失败影响客流 |

### 6.4 惩罚分级（可被养成减免）

| 级别 | 后果 | 减免来源 |
|---|---|---|
| 轻 | 掉单 / 该顾客差评 | 无 |
| 中 | 赔款 `[待定]` 元 | 效率分支（减少赔款） |
| 重 | 今日客流 −`[待定]`% | 容量分支（降低惩罚幅度） |

首次遇到 QTE 的那一局（第 5 天教学），失败按"轻"处理，并给出"下次这样操作"的提示。

## 7. 事件平衡的硬约束（自检清单）

- [ ] 同一天不会同时出现"客流大幅下降"+"厨具故障"+"断货"三个稀缺性事件
- [ ] 任何事件都不能让当日营业额理论上限=0（避免必输日）
- [ ] 好事与坏事权重比 ≈ 4:6
- [ ] 事件文案与效果一致，无"提示涨了实际跌了"
- [ ] 一局内 QTE ≤ 3，事件 ≤ 4
- [ ] 所有事件在 `[待定: 3]` 个不同的种子下都能被触发到（可测性）
