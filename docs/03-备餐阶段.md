# 03 备餐阶段

> 《不烧心夜市挑战》策划案 · v0.1
> 上游：[02-备货阶段](02-备货阶段.md) ｜ 下游：[04-出摊阶段](04-出摊阶段.md)

**时段** 14:00-20:00 ｜ **时间预算** 360 分钟 ｜ **货币** 分钟 + 台面格 + 现金 ｜ **产出** 今日菜单、定价、已加工的食材/成品

本章是全作**策略密度最高**的一段。玩家在这里做的三个决定决定当天上限：

1. **上架哪些餐品** → 决定哪些属性达到门槛 → 决定哪几条词条激活（菜单构筑）
2. **把食材加工到哪一级** → 决定出摊阶段是"快"还是"慢"（时间置换）
3. **定什么价** → 决定客流与单均（弹性）

---

## 1. 阶段能力总览

| 能力 | 时间成本 | 空间成本 | 金钱成本 |
|---|---|---|---|
| 上架 / 下架餐品 | 0 | 摊位空间（格） | 0 |
| 设定售价 | 0 | 0 | 0 |
| 食材升阶（预加工） | 分钟 | 台面格（加工中占用）、储存格（产出） | 0 |
| 制作成品 | 分钟 | 台面格、储存格 | 0 |
| 临时采购 | 分钟 | 储存格 | 溢价货款 |
| 查看词条面板 | 0 | 0 | 0 |

> 关于原稿此处断句的「·需要」：补为"需要把餐品加工到可售状态，并决定先做哪样"，见 [假设-1](10-待确认项与假设.md)。
>
> 刻意规定：**改菜单与定价不消耗分钟**。菜单构筑是玩家最需要反复试错的地方，如果试错有成本，玩家会退化成"照抄昨日菜单"，词条系统就白设计了。时间只惩罚"体力活"（加工、跑腿）。

## 2. 菜单构筑与词条激活

### 2.1 属性 → 词条对照（12 条，详见 `配表/Trait` 与 `配表/TraitTier`）

| 词条 | 绑定属性 | 激活门槛 | 叠加方式 | 效果方向 |
|---|---|---|---|---|
| 速度为王 | 速食 | 3 款 | 阶梯 | 出餐时间逐档减免；4 档起惠及全摊（半额） |
| 吃饱了 | 主食 | 3 款 | 阶梯 | 买主食按概率多卖非主食餐品 |
| 好辣！ | 魔鬼辣 | 4 款 | 阶梯 | 买辣货按概率加购饮料 |
| 现做饮品 | 现做饮品 | 6 款 | 阶梯 | 缩短制作时间 |
| 现做的不烧心 | 现做食品 | 4 款 | 阶梯 | 提高利润 |
| 冰冰冰 | 凉菜 | 6 款 | 阶梯 | 1 档起免成品交付，后续档提份数与售价 |
| 滋滋响（新） | 炸货 | 4 款 | 阶梯 | 炸货成交概率追加出餐 |
| 干杯（新） | 饮品 | 5 款 | 阶梯 | 包装饮料利润与单客瓶数 |
| 炭火气（新） | 烤物 | 4 款 | 阶梯 | 连击上限与满意度 |
| 热乎（新） | 汤羹 | 3 款 | 阶梯 | 风味衰减减免 + 延长顾客耐心 |
| 甜上头（新） | 甜点 | 3 款 | 阶梯 | 抬高满意度、放宽 QTE 窗口 |
| 老卤（新） | 卤味 | 3 款 | 阶梯 | 份数上限 + 跨夜保留豁免 |

**跨词条共鸣（8 条，`配表/Resonance`）**：解辣搭档（辣+现做饮品）、下酒组合（炸货+饮品）、一餐够了（主食+汤羹）、夜市标配（速食+烤物）、冷盘双拼（凉菜+卤味）、甜辣风暴（甜点+辣货）、铁板双煞（烤物+炸货）、全摊大满贯（速食+炸货+饮料三线）。

> 共鸣把"选一个属性堆到死"变成"两条线都要养"。凑共鸣时菜单会自然变宽，而台面格又不允许无限变宽 —— 这是本阶段最主要的一对张力。

### 2.1.1 激活门槛的空间代价（`配表/校验报告` 四）

凑够门槛不只看款数，还要看台面格。按"最省空间的 N 款"计算：

| 词条 | 需上架 | 最低台面格 + 厨具 | 判定 |
|---|---|---|---|
| 速度为王 / 滋滋响 / 老卤 | 3~4 款 | 5~6 格 + 1~2 件 | 开局可达 |
| 吃饱了 / 好辣！ / 炭火气 | 3~4 款 | 6~9 格 + 2 件 | 开局可达 |
| 冰冰冰 | 6 款 | 12 格 + 2 件 | 开局可达 |
| 现做饮品 | 6 款 | 14 格 + 3 件 | **需扩容** |

初始台面 16 格的含义：开局能同时点亮 1~2 条低门槛词条，想凑「冰冰冰」或「现做饮品」必须牺牲其它上架位或先扩容。数值表若要调整，改 `Balance.surface_capacity_init`，不要改餐品的摊位空间。

### 2.2 上架款数的计算口径

```
上架款数(tag) = 今日菜单中「词条包含 tag」的餐品数量
```

- 只看**上架**，不看库存：库存为 0 的餐品仍计入上架款数（否则玩家会被迫每天重排菜单）。
  但这产生"空壳上架"漏洞 —— 见 [假设-10]，建议加一条：**当日可售份数为 0 的餐品不计入上架款数**，请在数值表里确认。
- 同一餐品的多个属性各自独立计数（酸辣粉同时给「魔鬼辣 现做食品 主食」各 +1 款）。
- 激活是**即时**的：菜单一改，词条面板立刻变。

### 2.3 菜单构筑界面必须显示的三件事

1. 每个属性的当前款数与下一档门槛：`速食 3/3 ✓ 一档 ｜ 5 款可达二档`。
2. 每条已激活词条的效果全文，参数已代入当前 X（如"好辣！：50% 概率多买 2 份饮料"）。
3. **提示最近的一步**：`再上架 1 款主食 → 吃饱了升二档`。这是本阶段的核心引导，缺了它玩家不会自己发现构筑空间。

### 2.4 组合示例（设计校验用）

上架：方便面（速食）+ 火鸡面（速食 魔鬼辣）+ 麻辣烫（速食 魔鬼辣）+ 淀粉肠（速食 炸货）+ 炸鸡排（速食 炸货 现做食品）
→ 速食 5 款（速度为王二档：全餐品出餐 −20%）、魔鬼辣 2/4（未激活）、炸货 2（无词条）、现做食品 1/4（未激活）

这条路径只吃一条词条。若改为 4 款魔鬼辣 + 4 款现做食品，则同时点亮好辣！与现做的不烧心，但速食就掉出二档 —— **这就是玩家每天要解的题**。

## 3. 空间：台面格与储存格

### 3.1 规则

```
台面占用 = Σ(已上架餐品的「摊位空间」) + Σ(已购厨具占用格) + 加工中临时占用
台面占用 ≤ 台面容量                       ← 硬约束
储存占用 = Σ(库存 食材/半成品/成品 折算格) ≤ 储存容量   ← 硬约束
```

- 「摊位空间」取自 `food.xlsx`，0~6 格。取 0 的餐品（可乐、汽水、柠檬水）是纯成品型，不需操作位。
- 厨具占台面格：锅大、炸锅小、冰柜最占地方 `[待定: 具体格数]`。
- 加工中的食材还要**临时**占用台面格 `[待定]`，这条会让"边加工边上架"互相挤占。
- 容量不足时禁止上架并高亮超出的那一项（不能只说"超了"，要指出是谁）。

### 3.2 空间作为取舍开关

台面格是给"想什么都做"的玩家设的刹车。典型取舍：

- 上炸全鸡（6 格）几乎吃掉半个摊子，但它能一次性给所有已激活词条 +5 层（特性）。
- 上 3 款 0~1 格的小吃，词条更容易凑门槛，但单份利润低。

数值表需要保证：`台面容量` 在开局时明显不够用（`[待定: 初期 ≈ 6~8 格]`），后期靠加成扩容到 `[待定]`。

## 4. 厨具

| 厨具 | 关联餐品（示例） | 占格 | 备注 |
|---|---|---|---|
| 锅 | 方便面、酸辣粉、螺蛳粉、火鸡面、关东煮、麻辣烫 | `[待定]` | 最多餐品依赖的厨具 |
| 炸锅 | 淀粉肠、黑椒肉肠、炸鸡排、炸鸡腿、炸全鸡、炸薯条、炸薯塔 | `[待定]` | 出餐时间偏长 |
| 制冰机 | 冰鲜柠檬水、酸梅汤、杨枝甘露、芒果西米露 | `[待定]` | |
| 榨汁机 | 鲜榨西瓜汁、鲜榨橙汁 | `[待定]` | |
| 豆浆机 | 豆浆 | `[待定]` | 单餐品依赖 |
| 冰柜 | 全部凉菜 | `[待定]` | 同时承担冷藏修饰（减缓风味衰减） |
| 无（`/`） | 可乐、汽水、柠檬水、椰奶 | 0 | 直接交付 |

规则：

1. **上架前置条件**：餐品的「所需厨具」若玩家没有，则该餐品不能上架 —— 除非该餐品「无对应厨具时可售卖成品 = 是」，此时代价是**只能卖已备好的成品**，出摊时无法现场制作。
2. **工位与排队**：一件厨具默认 1 个工位，同一时刻只能处理一份，其余排队 FIFO [假设-11]。这是出摊阶段"忙不过来"的根源，见 [04](04-出摊阶段.md) §4。
3. 厨具通过**局外解锁**与**每日加成**获得，局内不能临时买（保持空间决策的稳定性）。

## 5. 食材加工（本阶段的时间黑洞）

### 5.1 加工链

```
原料 RAW ──→ 食材 INGREDIENT ──→ 生半成品 SEMI_RAW ──→ 熟半成品 SEMI_COOKED ──→ 成品 FINISHED
   (0)           (1)                 (2)                    (3)                     (4)
```

加工只能沿链逐级推进，`stageIndex` 只增不减。每次升阶要满足：有对应厨具 + 花掉分钟。

```
升阶耗时 = Σ_份数 [ 单份升阶耗时(阶段i → i+1) × 份数 ] + 批次准备时间[待定]
```

单份升阶耗时表（所有字段 `[待定]`）：

| 升阶 | 所需厨具 | 单份耗时 | 备注 |
|---|---|---|---|
| 原料 → 食材 | 无（洗切） | `[待定]` | 不占厨具，只吃时间 |
| 食材 → 生半成品 | 无/锅 | `[待定]` | |
| 生半成品 → 熟半成品 | 锅/炸锅/制冰机等 | `[待定]` | |
| 熟半成品 → 成品 | 对应厨具 | `[待定]` | 完成后开始掉风味 |

### 5.2 时间置换：为什么要在备餐加工

| 策略 | 备餐代价 | 出摊收益 | 风险 |
|---|---|---|---|
| 全预加工成成品 | 吃满分钟 + 占储存格 | 出摊时取货即走（`D_take` tick） | 风味随等待下降，可能变废档 |
| 只做到半成品 | 省分钟 | 出摊现场做，占用厨具与 `D` tick | 高峰期排队、掉单 |
| 完全不加工 | 0 分钟 | 出摊从起始阶段做起，最慢 | 大概率卖不完 |

推荐的玩家心理曲线：第 1~2 天全部预加工（简单），第 3~4 天发现风味掉档导致差评，开始混合策略 —— 这需要 UI 明确显示"这份成品的风味现在是几档"。

### 5.3 批量的边界

- 加工以**份**为单位排队，`份数` 越大耗时线性增长（+批次开销）。
- 单日单餐品可制作份数上限 = `储存格可用量 / 单份占格`，同时受"今天卖得掉多少"的经济约束（做多了就是剩货）。

## 6. 定价

```
售价(餐品) ≥ 成本(餐品) × (1 + 最低毛利率[待定])
```

- 定价上限由系统给出软提示（超过某值客流概率骤降），不做硬锁。
- **相对昨日价格的变化影响客流**：用弹性式而非阈值 ——
  `客流修正系数 = 1 − 涨价弹性[待定] × max(0, (今日均价 / 昨日均价 − 1)) + 降价弹性[待定] × max(0, (1 − 今日均价 / 昨日均价))`
  涨价惩罚系数 > 降价奖励系数（损失厌恶），具体值 `[待定]`。
- 首日无"昨日价"时用同类餐品均价做基准。
- 「现做的不烧心」词条按**利润**加成，所以高价+该词条能滚出更高的层数收益。

## 7. 临时采购

备餐阶段允许补货，但明显吃亏：

| 维度 | 相对备货阶段 |
|---|---|
| 可选 SKU | 只有 `[待定: 30%~50%]` 的常规品，无稀有货 |
| 价格 | +`[待定: 30%~60%]` 溢价 |
| 时间 | 每笔 `[待定: 15~30]` min（备货阶段为 5 min） |
| 到货 | 立即 |

定位：**救火**而不是常规手段。玩家忘了买某食材时的兜底，代价必须痛。

## 8. 结束备餐前的校验清单

点「出摊」时执行以下检查，逐条给出结果：

1. 台面格是否超限（超限则该餐品无法上架）
2. 每款上架餐品的厨具是否满足；不满足的是否有可售成品
3. 每款上架餐品的**当日可售份数**是否 > 0
4. 已制作成品中处于「废」档的数量（警告，不计入可售）
5. 预计毛利：`Σ(售价 − 单份成本) × 预计销量`，给一个粗略的盈亏提示
6. 未用完的分钟数（提示可继续加工）
7. 已激活词条汇总 + 每条当前 X
