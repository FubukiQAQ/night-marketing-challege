# 13 · 美术自动化生产说明（HD 精细像素）

> 配套文档：`12-美术需求文档-高精度版.md`（v2.0）
> 工具位置：`tools/artgen.py`、`tools/artgen_all.py`、`tools/art_prompts.py`、`tools/build_ico_ui_hd.py`
> 产出位置：`assets/art_hd/`（与 `assets/art/` 旧版 16px 素材完全隔离，可整目录替换上线）

---

## 1. 生产分工

| 资产 | 生产方式 | 理由 |
|---|---|---|
| 食材 126 / 餐品 82 / 厨具 13 / 顾客·摊主·特殊立绘 / 场景 5 层 | **Qwen-Image-2.1-Turbo(NVFP4) 文生图 + perfectPixel 锁格** | 需要材质细节、光影层次，程序化画不出来 |
| 12 标签 / 12 词条 / 8 共鸣 / UI 九宫格 / 数字字形 / 遮罩 | **程序化逐像素绘制**（`build_ico_ui_hd.py`） | 要求轮廓与色值严格对应表格、可无损整数放大、状态成套，生成模型无法保证几何精度 |

**不使用图生图、不引用任何历史素材或旧色卡作为参考图**，全部为纯文本提示词 + 程序化几何，避免旧 16px 规格污染。

## 2. 单张素材的流水线

```
提示词(art_prompts.py)
  → ComfyUI 出图（Qwen-Image NVFP4，Euler / CFG 1 / 官方 8 步 sigma）
  → perfectPixel 锁格（grid_size = 目标尺寸 × 超采样2）  ← 关键：输出已是纯像素图
  → 2:1 最近邻抽稀（保持硬像素边）
  → 品红抠底（四角取样 + 边缘洪泛，硬 alpha，不产生半透明描边）
  → 1px 深色外轮廓（#080C12）
  → 裁到主体 bbox，整数倍放大/居中（禁止非整数缩放）
  → 无抖动调色板收敛（默认 ≤20 色）
  → PNG-32 导出 + 24px/16px 最近邻验证图 + 总览图
```

关键点：**perfectPixel 的 `grid_size` 直接等于目标尺寸**，所以不存在"先画大图再缩"的糊边问题，最终像素颗粒与目标分辨率 1:1 对齐。

## 3. 一张大图出多个素材（拼版 + 按内容分割）

同类别同规格的素材会合成一张图生成，速度提升 4~16 倍，并且同一张图内所有物件天然共享光照与调色板。

| 类别 | 单张拼版 | 生成画布 | 单元格 |
|---|---|---|---|
| 食材 32×32 | 4×4 = 16 个 | 1280×1280 | 320px |
| 餐品 48×48 | 3×3 = 9 个 | 1152×1152 | 384px |
| 餐品 64×64 / 厨具 64×64 | 2×2 = 4 个 | 1024×1024 | 512px |
| 顾客 / 摊主 | **一个角色的全部动作一张图**（5 个 → 3×2） | 1152×768 | 384px |
| 特殊立绘 160×160 | 一个角色的 3 个表情一张图（3×1） | 1536×512 | 512px |
| 场景层、96px 大设备 | 单张 | 1024×1024 | — |

### 3.1 不再假设"均匀网格"（修复切多切歪）

早期版本按固定格子切分，模型排版一不均匀就会**切到邻居、或把主体切歪**。现在改为**按内容分割**：

1. 整张图先抠出物件掩膜（四角取底色 + 边缘洪泛）；
2. 连通域标记，过滤碎片（面积 < 中位数 25%）；
3. **按行优先排序**（先按 y 聚类成行，再按 x 排序），依次对应本批素材；
4. 每个物件取**自己的外接框（+3px 内边距）**裁切 —— 天然不会切到邻居、也不会偏心；
5. 裁切块先用品红补齐到目标宽高比再锁格，避免拉伸变形。

**判定与兜底**：
- 物件数 ≠ 期望数（粘连 / 缺失 / 多余）→ 抛 `LayoutMismatch`；
- 此时**同一次运行内立即降级为单张生成**这批素材（不等下一轮），并在状态里记录 `sheet-layout-mismatch`；
- 物件贴到整张图边缘 → 标记为可能被画布切断（`bleed`）。

### 3.2 角色帧间一致性（同一个角色 = 同一张拼图）

同一个角色的多个动作/表情**固定放在同一张拼图里**生成：提示词只描述一次角色本体，再逐格给动作。

```
character sheet, the SAME character in 5 poses, 3×2 grid, flat magenta background;
a chibi student customer, navy school uniform with white collar, backpack;
identical design / outfit / body proportions / hairstyle / palette in every cell,
only the pose and expression change: cell1 等待 … cell5 离开;
each figure fully inside its own cell, wide magenta gap …
```

行走/等待/催促/满意/离开由**同一次采样**产出，服装、体型、配色天然一致 —— 把"相邻帧一致性"从后期修改变成生成期约束。60 个角色素材因此合并为 14 张图（8 类顾客各 1 张 + 摊主 1 张 + 5 个特殊顾客各 1 张）。

### 3.3 自动质量门槛（每格独立判定）

- 覆盖率 <0.12 → 空白格；>0.88 → 溢出；主体贴边 → 疑似切断（`--strict` 视为失败）；
- 抠底后几乎全透明（<5%，说明没出纯色背景）→ 判失败重试；
- 不合格项写入状态文件，下一轮自动以单张模式重试（最多 4 次）。

### 3.4 场景层分支

`mode=frame`：不抠底、不描边、不留边距，锁格到 480×270 后整数 2 倍放大到 960×540，保证满幅与像素密度一致。

## 4. 断点续跑与原图备份

进度写在 `assets/art_hd/_state.json`，**每完成一格就落盘**：

- 随时 Ctrl+C、关窗口、断电都不丢进度；
- 再次运行同一条命令自动跳过已完成项、续跑剩余项；
- 失败项保留 `attempts` 计数，超过 4 次不再自动重试（用 `--retry-failed` 重置）；
- 日志追加到 `assets/art_hd/_run.log`，每张图后打印进度与剩余 ETA。

**原图备份**（每张图生成后立即归档，永不覆盖）：

| 位置 | 内容 |
|---|---|
| `_raw/sheet_<列>x<行>_<首个素材>__<原名>.png` | 整张拼图原图（模型原始输出） |
| `_raw/single_<素材id>__<原名>.png` | 单张生成的原图 |
| `_raw/cells/<素材id>__cell<N>.png` | 每一格的裁切原图（未抠底、未量化） |

状态里同步记录 `raw_backup` / `raw_cell` / `cell_bbox` / `sheet` / `cell` 序号，出问题时可直接对照原图复查，或拿裁切原图重新后处理，不必重新生成。

## 5. 怎么跑

```bat
:: 0) 先确认 ComfyUI 在跑（RUN_ART.bat 会自动拉起）
D:\QwenImage\start_comfyui.bat

:: 1) 只看队列与预计耗时，不生成
RUN_ART.bat --plan

:: 2) 分批跑（推荐：每次挂 30~60 分钟）
RUN_ART.bat --categories ing --max-gen 12
RUN_ART.bat --categories food --max-gen 8
RUN_ART.bat --categories utensil,char --max-gen 6

:: 3) 一口气跑完（约 40 分钟，57 张图）
RUN_ART.bat

:: 4) 单独补某几个
RUN_ART.bat --only food_lamb_skewer,ing_chili --sheet off

:: 5) 重跑失败项
RUN_ART.bat --retry-failed

:: 6) 强制重出（忽略已完成）
RUN_ART.bat --categories food --regen
```

程序化图标/UI（几秒，不占 GPU）：

```bat
D:\QwenImage\venv\Scripts\python.exe tools\build_ico_ui_hd.py
```

## 6. 时长与显存

- 单张生成 **约 36~40 秒**（RTX 5070 Ti Laptop 12GB，NVFP4，1024²级画布）。
- 全量队列：**296 个素材 → 57 张图 → 约 40 分钟**（单张实测 36~40 秒；角色按角色成组后张数减少）。
- 若 1280² 画布出现显存不足：加 `--sheet 2x2`（每张 4 个）或 `--sheet off`（逐个出图），速度换稳定。
- `--max-gen N` 限制本次发起多少次生成，适合"每天挂一会儿"。

对照文档 §9 的验收项，本管线自动保证：无抗锯齿/无半像素/无非整数缩放、PNG-32、图标不烘焙文字、标签色彩与轮廓成对、提供缩图验证页、每类附总览图。

## 8. 需要人工收尾的部分（如实说明）

1. **场景五层分离**：目前每层是独立生成的一张完整图，`far/mid/ground/near/light` 的遮挡关系与可编辑分层需要美术在 Aseprite/Photoshop 里按层重绘或做遮罩切分；`light` 层建议直接用程序化的 dither 光斑（`ui_mask_dither` 可复用）。
2. **动画帧**：文档要求 idle/work 6 帧、顾客 5 动作 × 4~6 帧。当前管线出的是**每个动作一张静帧**，且同角色的动作同版生成（一致性已有保障）；真正的过渡帧仍需基于静帧补绘或骨骼变形（像素资产不建议自动插值）。
3. **同角色一版内的微调**：同版生成保证了服装/体型/配色一致，但个别格子仍可能出现手势细节偏差，需美术在 Aseprite 里对齐一次。
4. **图标二次调优**：标签/词条是程序化首版，形准但细节偏简，需要美术在 32px 内加材质与高光。
5. **图集打包**：`assets/pack_atlas.py` 仍按旧目录 glob，切换 `art_hd` 后需改路径与文件名映射（新命名遵循 `类别_主体_动作_变体_序号.png`，如 `food_sour_spicy_noodle.png`）。

## 9. 与旧资产的关系

`assets/art/`（v1：16px 食材 / 24px 餐品 / 640×360 场景）保持不动，供当前版本继续跑；`assets/art_hd/` 为高精度版，验收通过后整体替换。
