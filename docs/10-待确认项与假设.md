## 一、假设清单（20 条，其中 18~20 为最新一轮裁决）

| 编号 | 假设 | 理由 | 影响范围 |
|---|---|---|---|
| 假设-1 | 原稿备餐阶段第 17 行断句「·需要」补为：**"需要把餐品加工到可售状态，并决定先做哪样"** —— 即备餐的核心是"预加工排产" | 与后文"食材阶段"与"节省备餐时间"两条自洽；出摊只有 60 秒，不给预加工留空间就没有策略 | [03](03-备餐阶段.md) §5 |
| 假设-2 | `1 tick = 1.2 游戏秒`，出摊共 12000 tick 对应店内 4 小时 | 让 `50 tick = 店内 1 分钟`，与 `food.xlsx` 出餐时间取值吻合 | [00](00-术语表与约定.md) §2、[04](04-出摊阶段.md) §1 |
| 假设-3 | 定价对客流的影响用**连续弹性式**，不当阈值处理；涨价惩罚系数 > 降价奖励系数 | 阈值会让玩家卡在悬崖上不敢调价，弹性式让"微调"也有意义 | [03](03-备餐阶段.md) §6 |
| 假设-4 | `food.xlsx` 的「摊位空间」= 该餐品上架后常驻占用的**台面格**；0 = 纯成品型不占操作位 | 让"空间"成为菜单构筑的硬约束（否则该列无意义） | [00](00-术语表与约定.md) §3.4 |
| 假设-5 | 「原料」与「食材」视为**同级未加工物**，不做"原料需先处理成食材"的额外链路 | 现有配方里两者都直接进加工链且都无前置动作；多加一级只增加操作噪音 | [00](00-术语表与约定.md) §3.5 |
| 假设-6 | 风味分 **5 档（优良普次废）**，仅"废"档不可售；档位同时影响售价系数与评价 | 需要一条硬底线来惩罚"全预加工"策略，但档位不宜太多 | [00](00-术语表与约定.md) §3.6、[04](04-出摊阶段.md) §6 |
| 假设-7 | 现金不允许为负；不足时进入"赊账"（结算扣息）而不是直接拒绝 | 增量游戏里"卡死不能玩"比"稍微吃点亏"体验差得多 | [01](01-核心循环与时间轴.md) §4 §5 |
| 假设-8 | ~~词条层数每日清零~~ → **已废弃，改为假设-18（层数永久累积）** | 用户裁决：不给玩家设上限，玩家玩成什么样由玩家自主决定 | [01](01-核心循环与时间轴.md) §4 |
| 假设-9 | 食材与半成品**不会腐败**，只有成品会掉风味 | 把复杂度集中在出摊段；备货段再叠腐败会让前期决策变成负担 | [02](02-备货阶段.md) §4 |
| 假设-10 | 当日可售份数为 0 的餐品**不计入**上架款数 | 否则玩家可以"空壳上架"白嫖词条激活，构筑系统会被绕过 | [03](03-备餐阶段.md) §2.2 |
| 假设-11 | 每件厨具默认 **1 个工位、FIFO 排队**，拥堵时会额外惩罚出餐时间 | 制造"忙不过来"，让多品类/多厨具构筑有价值 | [03](03-备餐阶段.md) §4、[04](04-出摊阶段.md) §4.2 |
| 假设-12 | 特性描述里的「所属已激活词条」= **该餐品自身拥有且当前已激活的全部词条**；「随机已激活词条」= 全场随机一条 | 现有 6 种写法需统一成一套可执行规则 | [04](04-出摊阶段.md) §5.1 |
| 假设-13 | 评分→次日客流系数**不叠加**（只看最近一天） | 防止负螺旋无限加深导致必输局 | [05](05-评分与养成.md) §2 |
| 假设-14 | 即使 7 天全低分，整轮经验也**保底够点 1 个技能点** | 增量游戏必须有"输也有进展"的兜底 | [05](05-评分与养成.md) §3 |
| 假设-15 | QTE 弹层期间**只暂停该顾客相关队列**，其余摊位继续运转 | 全暂停会打断节奏感；不暂停则玩家会漏操作。折中方案 | [06](06-随机事件与QTE.md) §6.1 |
| 假设-16 | 一局内 **QTE 不重复同一类型**，最多 3 次 | 60 秒里的操作要有变化，避免"又是连点" | [06](06-随机事件与QTE.md) §6.2 |
| 假设-17 | **不设硬性失败判定**；低分只通过客流下降形成压力，另设"摊主危机"兜底事件 | 7 天短局里，"第 3 天必死"会让大部分人再也不开第二局 | [01](01-核心循环与时间轴.md) §5 |
| 假设-18 | **词条层数永久累积、不设上限**（跨日跨轮保留）；控速改为三条：触发所需销量 `N(X)=N0×(1+X/G)`、单餐品每日触发上限 K、阶梯阈值 `T(n)=T0×r^(n-1)` | 你是这个取向。用"越来越难涨"替代"封顶"，玩家的成长曲线完全由自己的构筑决定 | [01](01-核心循环与时间轴.md) §4、[04](04-出摊阶段.md) §5.1.1 |
| 假设-19 | 叠加方式**只用三种**：阶梯档位、跨词条共鸣、层数来源扩展。不做乘算叠层、不做易失（掉层）、不做溢出转化 | 你选的组合。乘算容易后期爆，易失会劝退，溢出转化增加理解成本 | [00](00-术语表与约定.md) §3.3、[04](04-出摊阶段.md) §5.4 |
| 假设-20 | 数据规模定为 **12 属性 / 12 主词条 + 8 共鸣 / 82 餐品 / 126 食材 / 13 厨具**，旧表内容全部保留并改写 | 你要求"词条 ≥10、标签 ≥8、餐品 ≥70"，已超额交付 | [07](07-数据表结构.md) §1 |

## 三、开放问题（不阻塞开发，但影响手感）

1. **备货界面形态**：卡片列表（1 周开发） vs 地图行走（3 周）。地图更有"逛夜市"的感觉，但会让每天多花 2 分钟在走路上。倾向：先做列表，验证乐趣后再考虑地图。
2. **出摊视角**：俯视摊位 / 侧视 / 第一人称柜台。倾向侧视 —— 最能表现"摊位忙碌"和"排队"。
3. **难度档位**：是否需要"轻松/正常/硬核"？影响事件权重与目标营业额。倾向后置。
4. **自动排产**：给不给"一键把食材加工到合适阶段"的辅助？给了会削弱策略深度，不给会劝退新手。倾向做成技能树节点（效率分支）。
5. **是否加"外卖/线上接单"渠道**：能提供第二条收入曲线，但会让出摊段复杂一大截。倾向：不做，或作为第 2 轮内容。
6. **单轮时长**：目标 25~40 分钟现实时间。如果模拟下来超过 45 分钟需要砍天数或压缩演出。
7. **移动端是否首发**：影响 QTE 输入设计与布局。
8. **是否需要"经营数据图表"**（7 天营业额折线）：对增量向玩家很加分，成本低。倾向做。
